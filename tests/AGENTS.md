# 测试编写规范

本文件补充根 AGENTS.md，适用于 tests 下的实现与 CMake。CI 规则见 `../.github/AGENTS.md`。

## 每个新增或修改测试必须说明

- 要保护的不变量、输入域、单位、边界/退化行为及失败诊断；修复测试应能暴露对应旧错误。
- 唯一源码 owner、CMake target、CTest 名称/标签、适用平台与配置。优先扩展已有独立测试工程；禁止让同一测试源码被多个目录重复编译拥有。
- 生产依赖、共享 fixture、oracle 脚本/数据和必要下游；同步中央 CI 选择规则及直接命中、共享依赖、无关路径、删除/重命名回归。不能只监听本测试目录。
- 独立判据的来源与精度依据。解析解、守恒、物料平衡、相平衡、收敛后稳定性和独立参考各自验证，不相互冒充。Synthetic/manufactured fixtures 只证明其明确覆盖的软件或数学性质，不冒充实验物理验证。

## 结构与成本

1. 同一 Gate 在同一编译器/配置/验证模式下一轮只执行一次；上层集成测试不得重新拥有下层 CTest 的执行权，必要下游通过中央路由并集选择。
2. 公共头自包含探针使用独立 CTest 与可执行 target，禁止“编译但不调用”的伪覆盖。测试依赖、sanitizer 和编译选项保持 target-local，不传播给生产库消费者。
3. 共享 helper 放在明确的 tests/support ownership 下，不隐式跨目录引用私有 fixture；确有复用时声明消费者及 CI 路径依赖。
4. 新增测试不默认新增独立 PR workflow。每个切片只运行最小充分测试及必要下游，但保留科学容差、golden、严格告警和适用平台矩阵；不得删除失败样例或减弱断言来降本。
5. 生成数据、临时脚本、日志、构建目录和调试归档不提交；正式 fixture 必须可追溯且确被测试消费。参考生成必须可重复，不在生产实现中硬编码预期输出。
6. 报告区分静态审计、路由回归、编译、CTest、MPI/平台验证、物理验证和性能测量。没有执行就写未执行；skipped、cancelled、pending 不计为通过。性能改进须比较相同工作量，不能以减少覆盖冒充加速。
