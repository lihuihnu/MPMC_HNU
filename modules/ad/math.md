# AD 初等函数：定义域、异常与增量验证

公共头文件：`<mpmc/ad/math.hpp>`。仅包含本模块 `dual.hpp` 与 C++20 标准库；没有其他项目模块、第三方库、全局状态、录制 tape 或正常计算路径的堆分配。原 `dual.hpp`、算术测试和原 CMake 目标不变。以下是实数、一阶前向 AD 接口，不是复数、广义导数或符号化简系统。

## 1. 统一契约

所有**原值参数**必须有限，包括幂函数的底数与指数。非有限原值（NaN、正负 Inf）、定义域外输入以及本接口排除的不可微端点均抛出 `std::domain_error`；参数以只读引用或值传入，不改变调用方对象。Release 仍执行检查，不按 epsilon 裁剪输入，也不因为导数种子全零而跳过定义域检查。

这比底层 `<cmath>` 的值计算域有意更严格，例如 `sqrt(0)` 有值，但 `Dual` 版本不提供该点的有限导数；`asin(±1)`、`acos(±1)`、`acosh(1)` 同理。`abs(0)` 不选择任意次梯度。无法凭一阶种子判断整个复合函数在奇点是否可延拓，因此不猜测消去关系。

合法有限原值不保证结果可在 `T` 中表示。**上溢、下溢和非有限中间量遵循实际标准数学函数与浮点运算；不额外抛出 `std::overflow_error`，不夹紧结果、不将 NaN/Inf 改成有限数。** `errno` 与浮点环境标志不作为 AD API 的返回状态，也不由本模块保存或清零。不承诺全部平台的异常标志完全相同；后续将非有限结果传入另一个本头中的函数会因其输入契约而抛异常。

有效导数还要求有限且正确播种的输入导数。函数不另行扫描/校正种子；非有限种子可能产生非有限输出，不能认为有限原值代表梯度有效。某些恒等或常量幂分支可以直接返回输入或常量，不以 NaN 传播行为充当科学有效性判据。

导数按每个方向的链式法则传播，`N`、标量精度和所有权不变。结果不隐式转换到普通浮点数；C++20 下这些数学包装**不承诺 `constexpr`**。三角函数输入采用弧度；对数、指数和幂的物理量无量纲要求由领域调用方负责。

## 2. 一元函数逐项契约

下表中的 R 均额外受“有限可表示原值”约束。记 `s` 为输入方向种子，输出方向导数为 `f'(x) s`。每行在 CTest 中有独立的 `ad.math.<函数名>` 条目，覆盖 `float`、`double`、`long double`。

| 函数 | 本接口可微域 | 解析导数 f'(x) | 除非有限输入外的 domain_error 条件 |
| --- | --- | --- | --- |
| `exp` | R | exp(x) | 无 |
| `exp2` | R | ln(2)·2^x | 无 |
| `expm1` | R | exp(x) | 无 |
| `log` | x > 0 | 1/x | x ≤ 0 |
| `log2` | x > 0 | 1/(x·ln(2)) | x ≤ 0 |
| `log10` | x > 0 | 1/(x·ln(10)) | x ≤ 0 |
| `log1p` | x > −1 | 1/(1+x) | x ≤ −1 |
| `sqrt` | x > 0 | 1/(2·sqrt(x)) | x ≤ 0，含零导数奇点 |
| `cbrt` | x ≠ 0 | 1/(3·cbrt(x)^2) | x = ±0；负数可用 |
| `sin` | R | cos(x) | 无 |
| `cos` | R | −sin(x) | 无 |
| `tan` | R 中去掉 π/2+kπ | 1/cos(x)^2 | 计算得到 cos(x)=0 时拒绝；见下面说明 |
| `asin` | −1 < x < 1 | 1/sqrt(1−x²) | x ≤ −1 或 x ≥ 1 |
| `acos` | −1 < x < 1 | −1/sqrt(1−x²) | x ≤ −1 或 x ≥ 1 |
| `atan` | R | 1/(1+x²) | 无 |
| `sinh` | R | cosh(x) | 无 |
| `cosh` | R | sinh(x) | 无 |
| `tanh` | R | 1/cosh(x)^2 | 无 |
| `asinh` | R | 1/sqrt(1+x²) | 无 |
| `acosh` | x > 1 | 1/sqrt(x²−1) | x ≤ 1，含端点奇点 |
| `atanh` | −1 < x < 1 | 1/(1−x²) | x ≤ −1 或 x ≥ 1 |
| `abs` | x ≠ 0 | x>0 为 1，x<0 为 −1 | x = ±0 |

`tan` 的数学极点涉及无理数，二进制浮点数中的 `pi/2` 只是附近的数，不能按“等于一个舍入后的常数”就认定精确极点。实现不设置任意排除带；近极点可以返回很大的导数。大幅值三角函数的实参数约化精度取决于所用标准库，本模块不声称已验证所有大参数；没有用一个不可表示的“精确 π/2”伪造极点测试。测试覆盖 NaN/Inf、普通点以及极点附近可表示输入，零余弦保护作为运行时防护而非已命中的测试分支。

## 3. 幂函数的四种重载

| 调用方式 | 域与约定 | 导数 | 对应测试 |
| --- | --- | --- | --- |
| `pow(Dual x, int n)` | n≥0 时所有有限 x；n<0 时 x≠0 | n·x^(n−1)·dx；n=0 单独返回零导数 | `pow_integer` |
| `pow(Dual x, floating p)` | x>0；p 转换为 T 后必须有限 | p·x^(p−1)·dx | `pow_real` |
| `pow(Dual x, Dual y)` | x>0；y 有限；两者 T 与 N 相同 | y·x^(y−1)·dx + x^y·ln(x)·dy | `pow_dual` |
| `pow(scalar a, Dual y)` | a 转换为 T 后有限且 a>0；y 有限 | a^y·ln(a)·dy | `pow_scalar_base` |

整数指数采用多项式延拓约定：`pow(x,0)=1`，包括 `x=0`，其导数为零；`pow(x,1)` 在零点的导数为输入种子；负指数遇到正负零均抛异常。整数计算保持指数为整数，使用平方求幂和无符号幅值，覆盖 `INT_MIN`，不因将指数先转换为浮点数而丢失奇偶性。其标量求幂工作量为 O(log(|n|))，导数传播为 O(N)。

整数重载本轮只接收 **`int`**；`bool`、无符号及其他整数类型不隐式缩窄成该重载。浮点重载接受内建浮点指数，显式转换到 `T`，不提升 Dual 精度。需要其他整数宽度时另作有界性审计。

`pow(x,2)` 可以用于负数和零；`pow(x,2.0)` 按实指数接口要求正底数。即使 AD 指数的数值为整数、种子为零，也不扩大双变量函数的可微域。负数的实立方根使用 `cbrt`，不要用浮点指数 `1.0/3.0` 冒充精确有理数。

四种重载都测试合法值、解析偏导数、异常输入和参数不变；双 AD 重载同时验证底数与指数导数，特别检查 y=0 时不能错误消除指数方向的 ln(x) 项。

## 4. 数值安排与局限

`log` 直接计算 `s/x`，不先形成 `1/x`；`log10` 分拆除法，避免 `x·ln(10)` 的非必要上溢。`atan/asinh` 使用 `hypot(1,x)`，`acosh` 分解平方差后分别除法，避免直接构造 `x*x`。`asin/acos/atanh` 使用 `(1−x)(1+x)`。

`expm1` 的值通过标准库专用函数计算，导数另算 `exp(x)`，不使用 `expm1(x)+1`，因此值舍入为 −1 后仍可保留很小的非零导数。`tanh` 令 `u=exp(−abs(x))`、`q=u/(1+u²)`，按 `(s*q)*(4*q)` 传播；不在输出已舍入为 ±1 后做 `1−tanh(x)²`。这也保留部分大种子与极小局部导数相乘后的可表示结果。

上述安排仅消除明确分析过的风险，**不是任意动态范围的稳定性保证**。幂函数的中间幂或其他函数的局部因子仍可能提前下溢/上溢，混合方向可能相消；没有实现扩展指数、任意精度或整体缩放的求导系统。采用常量幂、解析缩放或重构必须保留数学问题，不得靠硬裁剪掩盖错误。未运行性能基准，不宣称优于成熟库。

## 5. 独立增量测试入口

为了使本次改动不触及原算术构建和测试，新增测试位于独立工程 `tests/ad/math`，仅消费 `mpmc::ad`：

```sh
cmake -S tests/ad/math -B build/ad-math -DCMAKE_BUILD_TYPE=Debug
cmake --build build/ad-math --target mpmc_ad_math_tests --config Debug
ctest --test-dir build/ad-math -C Debug -R '^ad[.]math[.]' --output-on-failure --no-tests=error
```

原根目录 `ad-debug` preset **仍只运行原算术测试**，不会隐式运行本新增工程。上面的独立命令才是本增量入口；不把未运行的新测试算进旧入口。正式执行证据以 GitHub 官方托管 runner 的对应提交日志为准。

30 个新增 CTest 条目：22 个一元函数、4 个幂重载，以及 `composition`、`range_regressions`、`overflow_policy`、`header_odr`。除固定 double 的双翻译单元链接检查外，条目均覆盖三种基础浮点类型；尺度回归另含针对 double 的极端输入。

逐函数的三个解析点来自手工可核对的恒等式，不从待测实现生成期望值。例如 `sinh(ln 2)=3/4` 且导数 `5/4`；`atanh(3/5)=ln 2` 且导数 `25/16`。每点使用方向种子 `[1,−2,0]` 和零种子，检查值、全部导数以及输入不变；按每个函数的域逐项测试边界/域外输入，并为每个函数测试 NaN 与正负 Inf。

链式组合 `exp(x*y)+log(x)+sqrt(y)+sin(x)` 在 9 个输入组合上核对解析梯度和独立 `J*v`。尺度回归覆盖近零 `log1p/expm1`、`expm1(-40)`、`tanh(±20)`、大参数 `atan/asinh/acosh`、次正规对数输入、结果幂下溢但导数可表示，以及近端点/近极点。范围行为在支持相应 IEEE 语义的平台检查。

无量纲短表达式沿用 64 倍 `T` 的机器 epsilon 作为绝对与相对容差；微小非零参考导数强制绝对容差为零，避免错误的零导数通过。没有差分生产求导、随机实验数据、参考值回填或硬编码成功结果。测试失败打印实际值、期望值和源码位置，Release 中不受 NDEBUG 影响。

## 6. CI 选择与复核

工作流读取 PR 的 base/head **两棵完整树的文件差异**，不只看最后一次提交。只改 `math.hpp`、`tests/ad/math/` 时只配置、编译并运行 `math` 工程；不编译/执行 `ad.dual` 或旧独立消费者。`dual.hpp`、模块构建等共享基础变动扩大验证范围；未知非文档路径保守选择两套测试。新增选择器有正常执行的分支回归检查。

该选择器不是完整的 C++/CI 语义依赖分析器：工作流单独改动默认运行两套测试；工作流伴随源码改变时，由编写前审计确认编译器、编译选项、平台环境是否还影响另一套测试。存在影响必须手动 `workflow_dispatch` 选择 `all`，不能因路径命中 math 就绕过旧测试。本轮原算术文件/目标不变，CI 改动用于新增测试路由，旧套件的编译器与告警/数值选项不变，因此只运行新增套件。

新数学头跨三个已建立的编译器入口验证：Linux/GCC Debug + ASan/UBSan、Linux/Clang Release、Windows/MSVC Release。它们只运行新增 30 条目，不运行无关全量回归、macOS 或性能基准。手动 `all` 可以分别运行两个独立测试工程；合入不重复执行相同代码树。

## 7. 参考与未包含能力

参考 [Ceres `jet.h`](https://github.com/ceres-solver/ceres-solver/blob/master/include/ceres/jet.h) 的初等函数接口及链式法则，审阅 blob `3672011fd6d45d1cc0c119a9ce02e56be3e5a7cd` 中相应函数；采用独立实现，不复制源码，不引入 Eigen/Ceres。有限原值与奇点异常是本模块的明确选择，不宣称和 Ceres 的边界行为相同。

其他核验入口：[autodiff 官方用法](https://autodiff.github.io/)、[C++ 标准草案数学头说明](https://eel.is/c++draft/c.math)、[NIST DLMF 三角恒等式](https://dlmf.nist.gov/4.21)和[双曲恒等式](https://dlmf.nist.gov/4.35)。当前标准草案不等于 C++20 的 constexpr 保证。

本增量不包括 `atan2/hypot` 的 AD 重载、特殊函数 `erf/gamma`、取整/比较/分支、动态维数、反向/高阶 AD、热力学及闪蒸，也没有调用外部 AD 库做对比测试。
